# Implementation plan

This is a single handoff with phased delivery. Finish all authorized implementation work; keep precise records of external inputs or asset work still missing. Do not stop at placeholder portraits plus a scripted office animation.

## Phase 0 — Establish a safe baseline

Read current instructions and Git status. Recheck apps/backoffice dependencies, schema, scripts and existing authenticated routes. Record current owner/access and financial invariants without printing private values. Preserve employee/ and all unrelated work. Use an isolated development checkout when appropriate and keep production processes running.

Evidence: baseline report, exact affected paths, installed compatibility plan, migration/recovery approach.

## Phase 1 — Canonical contracts and UI state specification

Adopt one set of stable agent IDs, task/run states, event types, artifact versions and approval scopes from data/response-presets.json. Persist server state; keep client animation state separate. Define /team Office layout, list mode and owner inbox. Produce a small screen/state review before broad component work.

Evidence: state transitions, role/output schemas, server authorization mapping, queue/worker contract, UI loading/empty/error/offline/demo states.

## Phase 2 — Scene and asset proof, with a usable conventional UI

Implement the page shell, profiles, task list and selected-agent panel. Use the measured floor plan to make a real 3D graybox with modular room/furniture geometry. Import one production-quality rigged character and verify the agreed animations at actual office zoom. If production assets are missing, label provisional geometry honestly and keep their milestone open. Build scene selection, focus/reset/pan/zoom and reduced motion. All tasks remain usable through list mode if 3D is unavailable.

Evidence: Chrome desktop screenshots, one-character animation/scale checks, geometry/path checks, artifact provenance, performance measurements on declared hardware. A concept PNG displayed in a canvas is not a real 3D proof.

## Phase 3 — Durable work and honest observation

Implement additive tables and worker dispatch/leases/checkpoints with fake adapters on a disposable database. Add authenticated state snapshots and bounded event replay. Exercise concurrent claims, restart/retry, cancellation, stale approvals, budget limits and cross-client denial before enabling live tools.

Evidence: focused regression results, restart and duplicate-effect scenarios, server authorization checks, owner/financial regression evidence. Demo events are labelled and isolated from live history.

## Phase 4 — Complete the office assets and presentation

Produce/import all manifest assets: seven recognizable rigged avatars, shared verified animations, room/furniture/props, anchors and walkable routes. Reconcile every model to the authoritative dimensions and conventions. Bake static light/shadow detail where appropriate, reuse resources and tune quality. Check all seven moving at once, labels, occlusion, seats and path intersections. Preserve source models and licenses alongside deliverable GLBs.

Evidence: asset acceptance report with real paths/hashes, source/license records, all animations checked, no placeholder claimed final.

## Phase 5 — One bounded live workflow

After the owner configures a provider and budget, process an internal website request into a qualified brief, scope/milestone draft and role recommendations. Assign an independent review and show artifact-version-specific owner acceptance. No messages sent, invoices issued or deployments executed by this pilot. Each role can be assigned bounded steps, but all seven need not make paid calls for every task.

Evidence: real task/run/event/artifact/approval IDs, actual usage, review evidence and known limitations. If credentials remain unconfigured, the live acceptance remains pending while offline deliverables finish.

## Phase 6 — Production readiness and activation

Prepare a reviewed additive migration, owner/access/financial preservation checks, backup/recovery procedure, worker supervision instructions and rollback. Deploy/activate only under the owner's authorization and an agreed window. Verify signed-in and denied routes, worker heartbeat, proper loopback binding and one harmless real task. Keep public website, shared tunnel and other database listeners unaffected.

Evidence: release report, exact checks performed, remaining asset/input gaps, activation state and rollback instructions. No GitHub Actions or paid CI without separate authorization.

## Completion reporting

Report separately:
1. specification/configuration integration;
2. browser visual prototype;
3. modeled 3D asset completion;
4. durable worker implementation;
5. verified live agent workflow;
6. production activation.

Each has its own pass/fail/pending status and evidence. A missing external input does not justify claiming success, but it also should not prevent unrelated implementation work.
