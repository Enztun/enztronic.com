## Defaults that let implementation progress

- Reuse the private backoffice and dedicated Postgres setup.
- Keep /team protected and relabel it Office; source human access management moves separately without changing membership/financial data.
- Use fake test adapters only in explicitly labelled test/demo mode.
- Leave live models, outbound tools and scheduled paid work disabled until configured.
- Missing production assets show a clear provisional/fallback state; continue all independent UI/worker work and keep final modeled acceptance pending.
- Initial real pilot produces an internal proposal and review package. Sam/Theo's proposal-only capability in that pilot is not a ban on Codex implementing the office. Later coding tasks require their scoped executor capability and isolated client workspace.
- A localhost Windows worker can continue after Chrome closes while the PC remains available. The existing logon startup design does not provide PC-off availability.

## Minimum inputs needed before dependent activation

1. Approved model/provider connection and per-run plus monthly spend limits. Null/unset limits disable paid work; they do not mean unlimited spending.
2. First authorized client/project sources and, for coding execution, registered repository roots and isolation method.
3. Approved scope for external messages, financial finalization, publishing and deployment. The initial pilot includes none of these effects.
4. Host availability target and a permitted worker-supervision/activation window.
5. Approved production 3D models with source/license records, or authorization for the modeling/asset-production work.

These inputs are not prerequisites to completing unrelated implementation, fake-adapter tests, UI states, graybox geometry or the asset-production brief.
